# 2.3 — Entropy Probe Re-run (POLE-SFT)

**Module:** `experiments/entropy_probe.py`
**Depends on:** 2.1 (`checkpoints/sl_adapter/`), 2.2 (`probe_utils`, locked `diversity_penalty`)
**Consumed by:** documentation / `project-overview.md` §7; informs whether 3.3/3.4 trust the
Bayesian secondary signal. **Not a build blocker** — the LLM self-assessment is the primary
signal regardless of this result.

---

## Objective

Re-run the entropy probe — previously run on a general `llama3.1-8b-text2cypher` checkpoint
(AUC ≈ 0.62) — now on the **POLE-specific fine-tuned Schema Linker** (2.1) at the locked
`diversity_penalty` (2.2). Confirm the schema-entropy→ambiguity signal **improves** with
POLE-specific fine-tuning, and re-confirm that the scoring function (entropy vs dominance vs
normalisation) doesn't matter (the prior probe found ablations flat, ≤0.01 delta). This
validates that the Bayesian scorer (3.3) is a usable secondary signal before the Ambiguity
Detector (3.4) consumes it.

Output: `results/entropy_probe_pole.json` (AUC table + ablations) and a short written finding;
update `project-overview.md` §7 only if the result materially changes the LLM-primary /
Bayesian-secondary conclusion (record any such change in `decisions-log.md`).

---

## Method (reuses `experiments/probe_utils.py` from 2.2)

```python
# experiments/entropy_probe.py
"""Re-run the entropy probe on the POLE-SFT Schema Linker; report AUC + scoring-fn ablations."""
```

1. Load benchmark (125 items) and the POLE schema block; load the SL adapter via
   `HuggingFaceLLM(base, peft_adapter_path="checkpoints/sl_adapter")`.
2. For each item, generate k=5 diverse beams at the locked `diversity_penalty` (read from
   `config/schema_linker_inference.yaml`); cache the beams (`results/beams_pole.jsonl`) so
   ablations rescore without re-generating — the original probe's cached-beams pattern.
3. Compute three scores per item from the cached beams and their AUC vs `is_ambiguous`:
   - **H_norm (candidates)** — entropy over distinct pattern strings (`normalised_entropy`).
   - **H_norm (beams)** — entropy over raw beam slots (no dedup).
   - **Top-beam dominance** — `1 − max_pattern_probability`.
4. Report the AUC table and compare the headline (H_norm candidates) AUC to the ≈0.62 baseline.

Results table:

|---|---|---|
| H_norm (candidates) | … | 0.622 |
| H_norm (beams) | … | 0.624 |
| Top-beam dominance | … | 0.625 |

## Interpretation guidance (for the written finding)

- **AUC improves over 0.62:** expected; confirms POLE fine-tuning sharpens the signal. The
  Bayesian scorer (3.3) is a useful secondary input to the AD.
- **AUC flat or ≈0.62:** still acceptable — the design already treats the entropy signal as
  secondary and the LLM self-assessment as primary. Note it; do not change the architecture.
- **Ablations flat (≤0.01 delta across the three signals):** expected and consistent with the
  prior probe — the scoring function is not the bottleneck, beam diversity is. 3.3 may therefore
  use the simplest scorer (normalised entropy) without loss.
- This step **never blocks** pipeline construction; it is a documented validation checkpoint.

---

## Edge cases

- Cache beams to `results/beams_pole.jsonl` before scoring so the three ablations are computed
  from one generation pass (cheap, reproducible).
- Use the same per-item `gold_patterns` and normalisation as 2.2 for any coverage cross-check.
- If `diversity_penalty` in `config/schema_linker_inference.yaml` is absent, fail with a clear
  message pointing back to 2.2 — do not silently pick a default.
