# 10.3 — Mistral External-POLE Adapter Refresh

**Modules:** `config/schema_linker_train_pole_external.yaml` (new),
`config/query_generator_train_pole_external.yaml` (new), Kaya runners
`kaya/94_train_sl_pole_external.slurm` + `kaya/95_train_qg_pole_external.slurm` (new).
No pipeline code change — `experiments/train_schema_linker.py` /
`train_query_generator.py` + `pipeline/sft.py::run_sft` are reused **verbatim** (they
already accept `--train <yaml>`, `init_adapter_path_name`, and `output_name` from 7.4).
**Depends on:** 10.2 (`data/pole_ext_*` files), 2.1/2.4 (`run_sft` harness), the existing
frozen v2 adapters `checkpoints/mistral7b/{sl,qg}_adapter` (continue-SFT base). **GPU**
(v100, workflow §7).
**Consumed by:** 10.4 (the e2e run measures these adapters).

---

## Objective

Produce `checkpoints/mistral7b/sl_adapter_pole_external` +
`checkpoints/mistral7b/qg_adapter_pole_external` — the exact paths
`run_evaluation._resolve_model_specs` already constructs for
`dataset_version: pole_external` + a local `active_model` (via
`adapter_suffix_for_version("pole_external") == "_pole_external"`, wired in 9.3). Once these
exist, 10.4 runs by config alone with no code change.

## Approach — continue-SFT, exactly like 7.4

Mirror the v3 train YAMLs (`config/schema_linker_train_v3.yaml`,
`config/query_generator_train_v3.yaml`) — **continue-SFT from the v2 Ozsoy adapter**, not a
from-scratch retrain (keeps the general Cypher capability; hours not days per adapter):

- `config/schema_linker_train_pole_external.yaml`:
  - `model.init_adapter_path_name: "sl_adapter"` (continue from the frozen v2 adapter).
  - `training.output_name: "sl_adapter_pole_external"` (v2 + v3 adapters untouched).
  - `data.train_path: "data/pole_ext_sl_train_mixed.jsonl"`,
    `data.eval_path: "data/pole_ext_sl_eval.jsonl"` (pure external eval = in-domain
    generalisation).
  - Everything else identical to the v3 YAML: 2 epochs, `learning_rate: 1.0e-4`,
    `per_device_train_batch_size: 2` / `gradient_accumulation_steps: 16`,
    `max_seq_length: 3584`, **`bf16: false, fp16: true`** (Volta), `save_strategy: epoch`.
- `config/query_generator_train_pole_external.yaml`: same treatment with
  `init_adapter_path_name: "qg_adapter"`, `output_name: "qg_adapter_pole_external"`,
  `data/pole_ext_qg_train_mixed.jsonl` / `data/pole_ext_qg_eval.jsonl`.
- Runners `94`/`95` mirror `kaya/74_train_sl_v3.slurm` / `75_train_qg_v3.slurm` (`--gres=gpu:2`,
  `--time` inside the 72h cap, the `run_sft` resume-from-checkpoint + skip-if-saved behaviour
  from 2.1 already handles a re-queue). Invoke
  `python -m experiments.train_schema_linker --model_key mistral7b --train
  config/schema_linker_train_pole_external.yaml` (and the QG analogue).

No `run_sft`/CLI change is anticipated — 7.4 already added `init_adapter_path` + `output_name`
support. If something is missing, it is a small anticipated addition per 7.4's precedent
(record in the tracker row, not decisions-log, unless a contract changes).

---

## Acceptance criteria

1. Both continue-SFT runs complete on Kaya; `eval_loss` decreases over the 2 epochs on the
   external eval split; job IDs + losses recorded in the tracker row (7.4 provenance style).
2. Adapters saved to `checkpoints/mistral7b/{sl,qg}_adapter_pole_external`; v2 (`_`) and v3
   (`_v3`) adapters byte-untouched.
3. Quick intrinsic check (cheap, GPU): regenerate cached beams for a ~25-item external
   benchmark sample with `sl_adapter_pole_external` (reuse `experiments/probe_utils.py` /
   the `kaya/g1_*` harness) and record the sample Cov@5 in the tracker row. (Full G1 is 10.4.)

## Handoff

10.4 runs `run_evaluation` with `dataset_version: pole_external` + `active_model: mistral7b`;
`_resolve_model_specs` picks up these `_pole_external` adapters automatically.
