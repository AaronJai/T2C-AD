**Modules:** `pipeline/schema_linker/inference.py`, `pipeline/schema_linker/postprocessing.py`,
`pipeline/schema_linker/linker.py`
**Depends on:** 0.1 (`CandidateMapping`, `SchemaCandidate`, `SchemaElement`, `SchemaRepr`),
0.2 (`BaseLLM`, `GenerationConfig`, `Completion`), 0.3 (POLE schema), 1.2 (`build_sl_prompt`),
2.1 (`checkpoints/sl_adapter/`), 2.2 (locked `diversity_penalty`)
**Consumed by:** 3.2 (label scope), 3.3 (schema entropy), 3.4/3.5 (candidate context), orchestrator.

---

## Objective

Turn a question + `SchemaRepr` into a `CandidateMapping` — a **distribution** over schema
patterns per varying position, never an argmax. Diverse beam search produces k beams; the
postprocessing aligns them into candidate slots and normalises beam log-probs into per-slot
probability distributions. This distribution is the foundation of the whole disambiguation
contribution.

`(question: str, schema: SchemaRepr) → CandidateMapping`

## `inference.py` — generation config + completion → pattern

```python
# pipeline/schema_linker/inference.py
"""Diverse-beam generation config and completion-text cleanup for the Schema Linker."""
from __future__ import annotations

from pipeline.llm import GenerationConfig


def sl_generation_config(beam_k: int, diversity_penalty: float) -> GenerationConfig:
    """Fully-diverse beam search: one group per beam."""
    return GenerationConfig(
        max_new_tokens=128,
        do_sample=False,
        num_beams=beam_k,
        num_beam_groups=beam_k,
        diversity_penalty=diversity_penalty,
        num_return_sequences=beam_k,
    )


def extract_pattern_from_completion(text: str) -> str:
    """The completion text is already the generated continuation (0.2 strips the prompt).
    Take the first non-empty line and strip — the model is trained to emit the pattern then stop.
    """
    for line in text.splitlines():
        line = line.strip()
        if line:
            return line
    return text.strip()
```

> Score extraction is **not** re-implemented here. `HuggingFaceLLM.generate` (0.2) already
> returns `list[Completion]` with `text` (the generated pattern) and `score` (summed log-prob).
> Postprocessing consumes those directly.

## `postprocessing.py` — beams → `CandidateMapping`

```python
# pipeline/schema_linker/postprocessing.py
"""Transform k beam completions into a CandidateMapping (the novel step)."""
from __future__ import annotations

import math
from dataclasses import dataclass

from pipeline.llm import Completion
from pipeline.schema_linker.inference import extract_pattern_from_completion
from pipeline.types import CandidateMapping, SchemaCandidate, SchemaElement, SchemaRepr


@dataclass
class ParsedPattern:
    raw_text: str
    nodes: list[tuple]          # [(alias, label), ...]
    relationships: list[tuple]  # [(src_alias, type, tgt_alias, direction, props), ...]
    is_valid: bool              # False if unparseable OR uses labels/rels not in schema
    score: float                # the beam's log-prob (from Completion.score)


def parse_schema_pattern(pattern_text: str, schema: SchemaRepr, score: float) -> ParsedPattern:
    """Parse a Cypher pattern fragment into nodes/relationships and validate against schema.
    is_valid=False when: unparseable, a node label ∉ schema.node_labels, or a relationship
    type ∉ {p['type'] for p in schema.relationship_paths}. Property filters (incl. {active:true})
    are captured in the relationship/node `props`.
    """
    ...


def align_beam_candidates(parsed: list[ParsedPattern]) -> dict[str, list[tuple[SchemaElement, float]]]:
    """Find positions that VARY across valid beams → candidate slots.

    Algorithm:
      1. Establish the common structural skeleton across valid beams (positions where the
         label/rel-type is identical in every beam).
      2. Positions that differ → candidate slots, keyed positionally:
         relationships → "rel_1", "rel_2", … (in hop order); nodes → "node_1", ….
      3. For each slot, collect the distinct SchemaElements seen and SUM the log-scores of the
         beams exhibiting each (merging duplicate beams in log-space).
      4. Temporal variant rule: if some beams carry {active:true} on a relationship and others
         don't, that is a SEPARATE slot keyed "rel_{n}_temporal" — same rel type, differing
         property filter. (Detected as relationship_type with/without the active property.)

    Returns {slot_key: [(SchemaElement, summed_log_score), ...]} (unordered scores; normalised next).
    """
    ...


def normalise_candidate_scores(
    raw: dict[str, list[tuple[SchemaElement, float]]],
) -> dict[str, list[SchemaCandidate]]:
    """Softmax each slot's log-scores into probabilities; emit SchemaCandidate lists ordered
    by score desc with beam_rank assigned. Uses log-sum-exp for stability."""
    def logsumexp(xs: list[float]) -> float:
        m = max(xs)
        return m + math.log(sum(math.exp(x - m) for x in xs))

    out: dict[str, list[SchemaCandidate]] = {}
    for key, cands in raw.items():
        lse = logsumexp([s for _, s in cands])
        ranked = sorted(
            (SchemaCandidate(element=el, score=math.exp(s - lse), beam_rank=0) for el, s in cands),
            key=lambda c: c.score, reverse=True,
        )
        for i, c in enumerate(ranked, 1):
            c.beam_rank = i
        out[key] = ranked
    return out


def build_candidate_mapping(question: str, completions: list[Completion],
                            schema: SchemaRepr) -> CandidateMapping:
    """completions → CandidateMapping.

    1. Parse each completion (text, score) → ParsedPattern (extract_pattern_from_completion first).
    2. Drop invalid beams. If < min_valid remain, the caller (linker) decides (raises).
    3. If all valid beams are the SAME pattern (no varying slot): single-candidate mapping —
       one slot per element, score 1.0. This yields ~0 entropy downstream (confident/unambiguous).
    4. Else: align_beam_candidates → normalise_candidate_scores → mentions.
    5. CandidateMapping(question, mentions, beam_k=len(completions)).
    """
    ...
```

## `linker.py` — the stage class

```python
# pipeline/schema_linker/linker.py
from __future__ import annotations

from pipeline.llm import BaseLLM
from pipeline.schema_linker.inference import sl_generation_config
from pipeline.schema_linker.postprocessing import build_candidate_mapping
from pipeline.schema_linker.prompts import build_sl_prompt          # SHARED with training (1.2)
from pipeline.types import CandidateMapping, SchemaRepr


class SchemaLinkerError(Exception):
    """Raised when fewer than min_valid_beams parseable beams are produced."""


class SchemaLinker:
    """Fine-tuned LLM + diverse beam search. Backend injected (BaseLLM)."""

    def __init__(self, llm: BaseLLM, beam_k: int = 5,
                 diversity_penalty: float = 1.0, min_valid_beams: int = 1):
        self.llm = llm
        self.beam_k = beam_k
        self.min_valid_beams = min_valid_beams
        self._config = sl_generation_config(beam_k, diversity_penalty)

    def link(self, question: str, schema: SchemaRepr) -> CandidateMapping:
        prompt = build_sl_prompt(question, schema.to_prompt_string(include_properties=True))
        completions = self.llm.generate(prompt, self._config)
        return build_candidate_mapping(question, completions, schema)
```

> **`diversity_penalty` is injected, not hardcoded.** The condition builder (5.3) reads the
> locked value from `config/schema_linker_inference.yaml` (2.2) and passes it here. Default 1.0
> only if no config is present.
> **Backend constraint:** the Schema Linker requires real beam scores. `AnthropicLLM` returns a
> single completion with a sentinel score — it must not back the Schema Linker (5.3 enforces).

## Edge cases & known limitations

- **All-agree beams → single-candidate mapping** is correct, not a failure: it signals
  confidence, and the scorer (3.3) returns ~0 entropy.
- **Positional slot keys** ("rel_1", "rel_1_temporal") are the chosen design. A richer NL-span
  keying ("connected to" → slot) is a documented open question deferred from Pass 2; positional
  is sufficient for the benchmark. Don't add span extraction here.
- **Multi-hop alignment (3–5 hops)** assumes varying elements sit at the same structural
  position across beams. For structurally divergent beams (different lengths/branching) positional
  alignment can mis-slot. Evaluate on the 5-hop benchmark questions; if it's a real failure mode,
  record in `decisions-log.md` before adding graph-edit-distance alignment.
- **Confidently-wrong** (all beams agree on a *wrong* mapping) is undetectable by design and out
  of scope (project-overview §8) — proceeds silently.

## Acceptance criteria

Now (no GPU; hand-built `Completion` lists):
1. `parse_schema_pattern("(p:Person)-[:SUSPECTED_OF]->(i:Incident)", pole_schema, -1.2)` →
   `is_valid=True`, one relationship (SUSPECTED_OF, Person→Incident); an out-of-schema rel type
   → `is_valid=False`.
2. `align_beam_candidates` on the four-`Person→Incident` beam example (SUSPECTED_OF/WITNESSED/
   VICTIM_OF/INVESTIGATES, plus a duplicate SUSPECTED_OF beam) yields one slot `rel_1` with four
   distinct elements, the duplicate merged in log-space.
3. `normalise_candidate_scores` output per slot sums to ~1.0 and is ordered by score desc with
   `beam_rank` 1..n.
4. `build_candidate_mapping` returns a single-candidate mapping (score 1.0) when all beams are
   identical; a multi-candidate mapping otherwise.
5. The temporal example (LIVES_AT with vs without `{active:true}`) produces a `rel_1_temporal` slot.

Run for real on Kaya (the `mistral7b` SL adapter is trained and a GPU is available — see
`ai-workflow-rules.md` §7; submit a `kaya/*.slurm` job, do **not** load the 7B base on the login
node):
6. `SchemaLinker.link` runs over the 125-item POLE benchmark and reports intrinsic Cov@5/EM@1
   (gold pattern = `extract_schema_pattern` of the benchmark's `cypher_default`/interpretations).
   This is where 2.1's Cov@5 target (≥85%) is checked.
   **Known issue to resolve here (decisions-log 2026-06-15):** the 2.2 sweep measured
   `Cov@5 = 0.000` because every SL beam ends in a bare trailing `--` (the committed-pattern
   filter-suffix marker with nothing after it), so an exact normalised-string match against gold
   never fired. Resolving this is exactly `postprocessing.py`'s job — `parse_schema_pattern` parses
   the text into `SchemaElement`s, which should ignore the dangling suffix rather than match on it.
   Use the cached `results/beams_pole.jsonl` (GPU-free) as starting evidence before re-running on
   GPU. The held-out text2cypher split remains the optional informal spot-check from 2.1 only, not
   reported here.

## Handoff

`SchemaLinker.link(question, schema) → CandidateMapping`. 3.2 reads `mentions` to scope entity
labels; 3.3 reads relationship-type slot scores for schema entropy; 3.4/3.5 receive the full
distribution; the orchestrator calls `candidate_mapping.top1_mapping()` (0.1) on the unambiguous
bypass. The Schema Linker knows nothing about its consumers.
