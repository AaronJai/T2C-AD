**Modules:** `config/pipeline_v3_qwen.yaml` + `config/pipeline_pole_external_qwen.yaml` (new,

**Depends on:** 10.6 (Qwen adapters for both substrates), 10.1 (external graph on Kaya) +

**GPU + live Neo4j** (workflow §7).
**Consumed by:** the dissertation — completes the model × dataset matrix.

---

## Objective

Run the three-condition gated evaluation with fine-tuned **Qwen2.5-32B** on both the v3
("custom") and external POLE substrates, producing `results/*_qwen2.5-32b_v3.*` and
`results/*_qwen2.5-32b_pole_external.*` plus qualitative reports — so the write-up has a large
open-model SFT column beside 7.5's mistral-7B-SFT and Phase 8/9.3's claude-instruct columns.

## Configs (standalone, 7.3/9.3 convention)

Both mirror the existing pipeline config shape, differing only in
`dataset_version`/`active_model`/`benchmark`/`results_tag`:

- `config/pipeline_v3_qwen.yaml`: `dataset_version: v3`, `active_model: qwen2.5-32b`,
  `benchmark: data/benchmark-v3.json`, `results_tag: v3_qwen`, neo4j → the `70_neo4j_v3`
  graph.
- `config/pipeline_pole_external_qwen.yaml`: `dataset_version: pole_external`,
  `active_model: qwen2.5-32b`, `benchmark: data/benchmark-pole-external.json`,
  `results_tag: pole_external_qwen`, neo4j → the 10.1 graph.

`ad: null`/`dis: null` → base Qwen runs AD/Dis (consistent with the mistral runs; a stronger
`ad`/`dis` swap is the documented optional lever). `_resolve_model_specs` maps
`active_model: qwen2.5-32b` + each dataset's `adapter_suffix` to the 10.6 adapters
automatically — no code change.

## SL decoding

Add a `decoding[qwen2.5-32b]` entry to `config/schema_linker_inference.yaml`. Lock it via the
G2a sweep (per substrate) in the gate chain, or reuse mistral's `diversity_penalty: 1.0` as a
documented pragmatic default if the sweep is skipped for budget (say which, per 9.3 precedent).

## Gates (7.5 methodology, per substrate, cheapest-first)

For **each** of v3 and external POLE, run G0→G4 (G1 full Cov@5/EM@1 with the Qwen SL adapter;
G2 sweep+probe; G3 AD probe; G4 full e2e). Do not skip past a failed gate; a G1 < 0.60 loops
back to 10.6 (more data/epochs) and is documented. v3's 120×3 and external's 100×3 are the two
G4 runs.

## Reporting

Re-score the 7 success criteria (project-overview §9) for Qwen on both substrates and extend
the `docs/results-walkthrough*` scorecards to a full matrix:
mistral-7B(SFT) | claude-sonnet(instruct) | qwen-32B(SFT), across v2 / v3 / external-POLE where
each applies. This is the model-capability axis of the substrate-vs-architecture-vs-model
argument.

## Acceptance criteria

1. Each gate's headline numbers + job IDs recorded per substrate (7.5 provenance style); no
   gate skipped past a failure; any G1 loop documented.
2. Both G4 runs complete (v3 120×3, external 100×3) with 0 tracebacks; the eight Qwen artefacts
   (tables/metrics/qual_records/qualitative_analysis × 2 substrates) written under the
   `v3_qwen` / `pole_external_qwen` tags.
3. `analyze_qualitative.py` run for both; per-type buckets non-empty.
4. Scorecard(s) updated to the three-model matrix; **all prior artefacts untouched** — mistral
   v2/v3/external and claude v3/external results in `results/` and `docs/` are byte-unchanged.

## Handoff

Phase 10 complete: the dissertation has (a) the external POLE graph reproducible on Kaya, (b) a
fine-tuned-Mistral column on external POLE closing the 9.3 gap, and (c) a large open-model
(Qwen2.5-32B, SFT) column across the custom v3 and external POLE substrates — the full
model × dataset evaluation matrix the GPU upgrade made feasible.
