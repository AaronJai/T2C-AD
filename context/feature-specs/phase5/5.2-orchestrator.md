# 5.2 — Orchestrator

**Module:** `pipeline/orchestrator.py`
**Depends on:** 0.1 (`PipelineState`, `SchemaMapping`, `Condition`, `BenchmarkItem`), 3.1–3.8
(all inference stages), 4.1 (`semantic_evaluator`), 5.1 (`PipelineComponents`). 6.1
(`cosine_prefilter`) imported lazily, only if `use_prefilter`.
**Consumed by:** 5.3/5.4 (the harness calls `Orchestrator.run` per question per condition).

---

## Objective

Drive one question through the pipeline for a given condition, managing the **three feedback
loops** and the **condition routing**, and return a fully-populated `PipelineState`. This is the
control-flow heart of the system.

`run(question, benchmark_item, condition, components) → PipelineState`

> Uses the **actual Phase 3 APIs**: `components.schema_linker.link(...)`,
> `entity_lookup(question, cm, components.entity_cache)`,
> `ambiguity_detector(..., components.ad_llm)`, `disambiguator(..., components.dis_llm, ...)`,
> `components.query_generator.generate(...)`, `cyver_validator(cypher, components)`,
> `db_executor(...)`, `semantic_evaluator(...)`. (The Pass-3 functional-style calls are superseded.)

---

## Loop structure & routing (the contract)

```
OUTER — schema retry            range(MAX_SCHEMA_RETRIES + 1)   # 3 → 4 iters
  trigger: CyVer route_to="schema_linker"; increments state.retry_count; clears previously_tried
  │
  └ DISAMBIGUATION — semantic retry   range(MAX_DIS_RETRIES + 1)   # 1 → 2 iters
      trigger: failure_mode=="wrong_result" (Condition 3 only); does NOT increment retry_count
      │
      └ INNER — syntax retry     range(MAX_SYNTAX_RETRIES + 1)   # 2 → 3 iters
          trigger: CyVer route_to="query_generator"; does NOT increment retry_count
```

| CyVer / eval result | Inner | Disambiguation | Outer |
|---|---|---|---|
| `accept` | break → execute | — | — |
| `query_generator` (syntax) | continue (retry QG) | — | — |
| syntax retries exhausted | break, `is_failed` | break | break |
| `schema_linker` (schema/props) | break, `schema_fail` | break | continue (retry SL), `retry_count++` |
| schema retries exhausted | — | — | break, `is_failed` |
| `wrong_result` (C3, budget left) | — | continue (next interpretation) | — |
| dis exhausted / `disambiguator→None` | — | break | break |
| correct / `valid_non_default` | — | break | break |

## Implementation

```python
# pipeline/orchestrator.py
from __future__ import annotations

from typing import Optional

from pipeline.ambiguity.detector import ambiguity_detector
from pipeline.components import PipelineComponents
from pipeline.disambiguator.disambiguator import disambiguator
from pipeline.entity_lookup.lookup import entity_lookup
from pipeline.evaluation.semantic_evaluator import semantic_evaluator
from pipeline.execution.db_executor import db_executor
from pipeline.types import BenchmarkItem, Condition, PipelineState, SchemaMapping
from pipeline.validation.cyver_validator import cyver_validator


class Orchestrator:

    def run(self, question: str, benchmark_item: Optional[BenchmarkItem],
            condition: Condition, components: PipelineComponents) -> PipelineState:
        state = PipelineState(question=question, benchmark_item=benchmark_item, condition=condition)

        # ── OUTER: schema retry ────────────────────────────────────────────────
        for schema_attempt in range(state.MAX_SCHEMA_RETRIES + 1):
            if schema_attempt > 0:
                state.retry_count += 1
                state.previously_tried_mappings = []   # fresh SL run → fresh candidate set

            # Stage 0: optional cosine pre-filter (6.1; lazy import so 5.2 predates it cleanly)
            if components.use_prefilter and components.embedding_model is not None:
                from pipeline.prefilter import cosine_prefilter
                state.filtered_schema = cosine_prefilter(question, components.schema,
                                                          components.embedding_model)
            working_schema = state.filtered_schema or components.schema

            # Stages 1–3: condition-dependent upstream
            if condition == "baseline":
                state.schema_mapping = SchemaMapping(question=question, committed={},
                                                     cypher_syntax="", resolution_mode="automated")
            elif condition == "schema_grounded":
                state.candidate_mapping = components.schema_linker.link(question, working_schema)
                state.schema_mapping = state.candidate_mapping.top1_mapping()
            else:  # disambiguation_enhanced
                state.candidate_mapping = components.schema_linker.link(question, working_schema)
                state.entity_lookup = entity_lookup(question, state.candidate_mapping,
                                                    components.entity_cache)
                state.ambiguity_result = ambiguity_detector(question, state.candidate_mapping,
                                                            state.entity_lookup, components.ad_llm)
                if benchmark_item is not None:          # Detection-F1 support (4.2)
                    state.ad_predictions.append(
                        (benchmark_item.question_id, state.ambiguity_result.is_ambiguous))

            schema_fail = False

            # ── DISAMBIGUATION: semantic-mismatch retry ────────────────────────
            for dis_attempt in range(state.MAX_DIS_RETRIES + 1):

                # Stage 4: Disambiguator (C3 only; C1/C2 keep the mapping set above)
                if condition == "disambiguation_enhanced":
                    if state.ambiguity_result.is_ambiguous or dis_attempt > 0:
                        new_mapping = disambiguator(
                            question, state.ambiguity_result, state.candidate_mapping,
                            state.entity_lookup, components.dis_llm,
                            previously_tried=state.previously_tried_mappings)
                        if new_mapping is None:
                            break                       # candidate set exhausted
                        state.schema_mapping = new_mapping
                    else:
                        state.schema_mapping = state.candidate_mapping.top1_mapping()
                    # record (dedup by cypher_syntax — the QG-facing string)
                    if all(m.cypher_syntax != state.schema_mapping.cypher_syntax
                           for m in state.previously_tried_mappings):
                        state.previously_tried_mappings.append(state.schema_mapping)

                # ── INNER: QG + CyVer syntax retry ─────────────────────────────
                for syntax_attempt in range(state.MAX_SYNTAX_RETRIES + 1):
                    state.generated_cypher = components.query_generator.generate(
                        question, state.schema_mapping, working_schema)
                    state.validation_result = cyver_validator(state.generated_cypher, components)

                    if state.validation_result.route_to == "accept":
                        break
                    elif state.validation_result.route_to == "query_generator":
                        if syntax_attempt == state.MAX_SYNTAX_RETRIES:
                            state.is_failed = True
                            state.failure_reason = "max_syntax_retries_exhausted"
                        continue
                    elif state.validation_result.route_to == "schema_linker":
                        schema_fail = True
                        break

                if state.is_failed or schema_fail:
                    break
                if state.validation_result.route_to != "accept":
                    break

                # Stage 7: execute
                state.execution_result = db_executor(
                    state.generated_cypher, components.neo4j_driver, components.database_name)

                # Stage 8: evaluate (is_first_attempt = the very first attempt for this question)
                is_first = (schema_attempt == 0 and dis_attempt == 0)
                state.evaluation_result = semantic_evaluator(
                    state.execution_result, benchmark_item, state.generated_cypher,
                    state.validation_result, condition, state.retry_count,
                    components.neo4j_driver, components.database_name,
                    embedding_model=components.embedding_model, is_first_attempt=is_first)

                # semantic-mismatch routing (C3 only)
                if (condition == "disambiguation_enhanced"
                        and state.evaluation_result.failure_mode == "wrong_result"
                        and dis_attempt < state.MAX_DIS_RETRIES):
                    continue
                break

            if not schema_fail or state.is_failed:
                break

        if schema_fail and not state.is_failed:
            state.is_failed = True
            state.failure_reason = "max_schema_retries_exhausted"

        return state
```

---

## Terminal states

| Exit | `is_failed` | `evaluation_result`? | Meaning |
|---|---|---|---|
| `is_correct=True` | False | Yes | correct |
| `valid_non_default` | False | Yes | valid, non-default interpretation |
| `wrong_result` + retries exhausted | False | Yes | wrong, no alternatives left |
| `max_syntax_retries_exhausted` | True | No | QG couldn't produce valid syntax |
| `max_schema_retries_exhausted` | True | No | SL couldn't produce a schema-valid pattern |
| disambiguator returned `None` | False | No | candidate interpretations exhausted pre-execution |

---

## Edge cases & invariants

- **`is_first_attempt`** is True only when `schema_attempt==0 and dis_attempt==0` — the first time a
  query reaches evaluation. Syntax retries (inner loop) re-run the QG before any evaluation, so they
  don't affect first-attempt status. This drives Pass@1 and the repair metrics (4.2).
- **`ad_predictions`** is appended once per outer iteration in C3 (after the AD runs), only when
  `benchmark_item` is present. 5.4 collects these from every C3 `PipelineState`.
- **`previously_tried_mappings`** clears on each outer (schema) retry — a fresh SL run yields a fresh
  candidate set — and persists across disambiguation retries (same candidate set). Dedup is by
  `cypher_syntax`, the QG-facing string.
- **C1/C2 run the disambiguation loop exactly once** — the `wrong_result` `continue` is C3-guarded,
  so they always `break` after the first iteration; Stage 4 is C3-guarded too, so their
  `schema_mapping` (empty for C1, top-1 for C2) persists untouched.
- **`disambiguator → None`** breaks the disambiguation loop with no `evaluation_result`; a terminal
  "exhausted" state (metrics count it as not-correct via absence).
- Lazy `cosine_prefilter` import keeps 5.2 implementable before 6.1 exists; default `use_prefilter`
  is False so the import never fires in the standard experiment.

## Acceptance criteria

Now (no GPU/DB; inject a fake `PipelineComponents` with stub stage objects/functions):
1. **Baseline path:** stubbed QG returns a fixed query, CyVer stub `accept`, executor stub returns
   rows, evaluator stub returns `is_correct=True` → one pass, no SL/AD/Dis touched,
   `evaluation_result.is_correct=True`, `retry_count=0`, `is_first_attempt=True`.
2. **Syntax retry:** CyVer stub returns `query_generator` twice then `accept` → QG called 3×, inner
   loop exits on accept, `retry_count` unchanged.
3. **Syntax exhausted:** CyVer always `query_generator` → `is_failed=True`,
   `failure_reason="max_syntax_retries_exhausted"`, no `evaluation_result`.
4. **Schema retry:** CyVer `schema_linker` once then `accept` → SL.link called twice, `retry_count=1`,
   `previously_tried_mappings` cleared between attempts.
5. **Schema exhausted:** CyVer always `schema_linker` → `is_failed=True`,
   `failure_reason="max_schema_retries_exhausted"`.
6. **C3 semantic retry:** evaluator stub returns `wrong_result` then `is_correct=True` → disambiguator
   called twice with growing `previously_tried`, final `is_correct=True`, `is_first_attempt` True only
   on the first evaluation.
7. **C3 exhausted candidates:** disambiguator stub returns `None` → loop breaks, no `evaluation_result`.
8. **`ad_predictions`** populated once per C3 outer iteration with `(question_id, is_ambiguous)`.

Deferred (live system): end-to-end over the benchmark in 5.4.

## Handoff

`Orchestrator.run(...) → PipelineState`. 5.4 calls it for every question × condition, reads
`evaluation_result` (→ `compute_metrics`) and, for C3, `ad_predictions` (→ detection metrics). 5.3
builds the per-condition `PipelineComponents` this consumes.
