# 6.2 — Gradio Demo (interactive-disambiguation stub)

**Module:** `app/gradio_demo.py`
**Depends on:** 0.3 (`build_pole_schema_repr`), 3.1/3.2/3.4/3.5 (stages, for the step-by-step and
interactive flow), 5.1 (`PipelineComponents`), 5.2 (`Orchestrator`, for automated mode), 5.3
(`build_condition3`). Uses `gradio`. **Requires a live Neo4j + the trained adapters.**
**Consumed by:** nobody downstream — this is a demo/extension, **never wired into evaluation**.

---

## Objective

Make the pipeline tangible: a local UI that shows the loaded models and Neo4j status, runs a typed
question through the full (Condition 3) pipeline, and — for ambiguous questions — demonstrates the
**interactive disambiguation** path that the evaluation harness stubs out. Automated mode is the
evaluated path; interactive mode is shown here only. The theoretical basis for interactive
clarification is Qiu et al. (EIG); this demo implements a lightweight version, not the full EIG
objective.

> **Why this exists.** 3.5's `disambiguator(mode="interactive")` raises `NotImplementedError` so the
> harness can't accidentally depend on a human. This demo implements the *interface contract* that
> stub describes — pose a clarification question, await a reply, then commit — purely for the UI.
> It does not change the evaluated pipeline and adds no metrics.

---

## Layout

- **Status panel** (rendered once at startup):
  - Base model + which adapters are loaded (`sl_adapter`, `qg_adapter`) and whether they're local
    paths or hub IDs.
  - Neo4j connection: `driver.verify_connectivity()` → ✓/✗, database name, entity-cache node count.
- **Mode toggle:** Automated | Interactive.
- **Question** text box + Run button.
- **Trace panel** (read-only): the candidate distribution, entity matches, ambiguity result
  (is_ambiguous, types, schema/entity entropy), committed mapping, generated Cypher, and the
  executed result rows. This surfaces the pipeline's internal decisions, which is the demo's value.
- **Interactive sub-panel** (visible only in Interactive mode when a question is flagged ambiguous):
  the clarification question + a reply box + Confirm button.

Key points:
- **Interactive mode does not call `disambiguator(mode="interactive")`** (that raises). It uses
  `generate_clarification_question` for the contract, then commits via the automated disambiguator
  with the user's answer folded in (or a direct candidate match), recording `clarification_qa` on the
  `SchemaMapping`.
- **Automated mode** is exactly the evaluated pipeline (`Orchestrator.run`), so the demo doubles as a
  faithful view of what the experiment does.
- `gr.State` carries the SL/entity/AD intermediate results between the two interactive steps.

## Edge cases & boundaries

- **Not evaluated, no metrics, no ground truth** — `benchmark_item=None`; the demo shows results,
  not EX/AREA. It must never be imported by `run_evaluation.py` or the metrics path.
- **Ambiguous-question detection** in interactive mode reuses the real AD; if the AD says
  unambiguous, the interactive sub-panel stays hidden and it commits top-1 (same as automated).
- **Neo4j down / adapters missing** → the status panel shows ✗ and the Run button surfaces a clear
  message rather than throwing.
- **Credentials** come from the environment (as in 5.4), never hardcoded.
- Keep the clarification generation lightweight; the full EIG expected-information-gain selection is
  cited (Qiu et al.) as the principled extension, not implemented here.

---

## Acceptance criteria

Mostly integration / manual (it's a UI):
1. `generate_clarification_question` (unit-testable with a stub `dis_llm`) returns a single question
   string enumerating the candidate options.
2. `_status` reports ✓ when `verify_connectivity` succeeds (stubbed) and ✗ on failure, without raising.
3. (Manual) launching `main()` against a live Neo4j + adapters shows the status panel; a clearly
   ambiguous question in Interactive mode pops the clarification sub-panel; answering it produces a
   committed mapping with `clarification_qa` set and an executed result.
4. The module is never imported by `experiments/run_evaluation.py` (grep check).
