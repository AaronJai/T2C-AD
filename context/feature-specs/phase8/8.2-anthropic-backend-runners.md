# 8.2 — Anthropic Backend Correctness + v3 API Gate Runners

**Modules:** `pipeline/llm/anthropic.py`, `experiments/diversity_penalty_sweep.py`,
`experiments/run_evaluation.py` (prompt_style wiring only), `kaya/g1_sl_coverage_v3.py`,
`kaya/ad_probe_v3.py`, new `kaya/api_smoke_v3.py` + slurm runners (+ tests).
**Depends on:** 0.2 (`BaseLLM`), 5.5 (API end-to-end), 7.3 (v3 config selection),
8.1 (`prompt_style` parameter). **No GPU; no API key needed offline** (fakes).
**Consumed by:** 8.3.

---

## Why this exists

Checked against the current Anthropic API rules for `claude-sonnet-4-6` (the registry's
`claude-sonnet` entry — chosen over Sonnet 5 precisely because 4.6 still accepts
`temperature`; Sonnet 5 rejects non-default sampling params with a 400):

1. **Greedy stages currently sample at temperature 1.0.** `AnthropicLLM.generate_chat`
   always sends `temperature=config.temperature` (default 1.0) and ignores
   `do_sample=False` — so QG/AD/Dis on Anthropic would be high-temperature samplers.
   That silently breaks the pipeline's determinism assumptions (the `error_feedback`
   retry design exists *because* decoding is deterministic) and thesis reproducibility.
2. **`temperature` + `top_p` together is a 400 on Claude 4.x models.** The code dodges
   it only because it never forwards `top_p` — i.e. the decoding blocks' `top_p: 0.95`
   is silently ignored today. Make the omission official.
3. **A multi-hour run needs retry headroom.** The SDK already retries 429/529/5xx with
   exponential backoff (honouring `retry-after`); default `max_retries=2` is thin for
   a ~3h unattended run.
4. The 7.5 gate runners are HF/GPU-hardcoded; the API run needs registry-driven,
   GPU-free siblings that serve the **v3** Neo4j volume (the 5.5-era
   `kaya/67_run_evaluation_api.slurm` mounts the v2 volume).

## Contracts

### 1. `AnthropicLLM` (`pipeline/llm/anthropic.py`)

- `do_sample=False` → send `temperature=0.0`; `do_sample=True` → send
  `config.temperature`. (Anthropic temperature range is 0.0–1.0; all swept values are
  valid.)
- **Never send `top_p`** (Claude 4.x rejects `temperature`+`top_p` together; sampling
  diversity is controlled by temperature alone on this backend). `GenerationConfig.top_p`
  is simply ignored here — OpenAI's backend keeps its existing behaviour.
- Construct the client with `max_retries=5` (SDK-native backoff; no hand-rolled retry
  loop). Multi-sample (`num_return_sequences>1` → N calls, uniform −1.0 scores) is
  unchanged.

### 2. Sweep decodings (`experiments/diversity_penalty_sweep.py`)

`candidate_decodings` becomes backend-aware: for `backend: anthropic` the swept
blocks are `{strategy: sample, temperature: T, k: 5}` with **no `top_p` key** (and the
block written to `config/schema_linker_inference.yaml` likewise carries none);
`backend: openai` keeps `top_p: 0.95`. The sweep's `main` already has the registry
entry to read `backend` from. Local (beam) candidates unchanged.

### 3. `prompt_style` wiring (from 8.1)

`run_evaluation`, the sweep, and the probe pass `prompt_style="instruct"` to
`SchemaLinker` / `generate_beams` when the active registry entry is `kind: api`
(derive it next to the existing `_resolve_sl_decoding` kind branch); `"completion"`
otherwise. Local path byte-identical.

### 4. Gate runners (kaya)

Numbering indicative — keep the 7.5 convention (`logs/<name>_<jobid>.out/.err`, v3
Neo4j served in-job from `$MYGROUP/neo4j_data_v3` per `70_neo4j_v3.slurm`, `work`
partition, **no `--gres`**, API-key guard as in 67):

- **`kaya/api_smoke_v3.py` + `kaya/82_api_smoke_v3.slurm` (G0.5).** 5–10 stratified v3
  questions: SL sampling k=5 (instruct prompt), one AD call, one Dis call, one QG call
  (committed-pattern and zero-shot). Writes a plain-text report of **raw completions
  side-by-side with their parsed patterns / extracted Cypher / parsed JSON**, plus:
  an egress check (fail fast with a clear message if `api.anthropic.com` is
  unreachable from the compute node) and a `count_tokens` measurement of the SL and
  AD/Dis prompt prefixes (prompt-caching viability: Sonnet 4.6 needs a ≥2048-token
  cacheable prefix — record the numbers; wiring `cache_control` is OPTIONAL and only
  if the AD/Dis prefix clears the bar).
- **`kaya/g1_sl_coverage_v3.py` generalised + `kaya/83_g1_coverage_api_v3.slurm`.**
  The G1 script resolves its LLM from the `config/models.yaml` entry for a
  `--model_key` arg (local → HF base + `{sl}_adapter{suffix}` exactly as today; api →
  `build_llm` on the API spec, sampling decoding, instruct prompt). Coverage needs no
  Neo4j and no GPU for the API path. Accepts an explicit `--decoding` override so G1
  can run pre-sweep (default temperature 0.7, k=5), mirroring 7.5's pre-sweep dp=0.2.
- **`kaya/84_sweep_api_v3.slurm`.** Work-partition sibling of `78_sweep_v3.slurm`
  running the temperature sweep with `--model_key claude-sonnet --dataset_version v3
  --results_tag v3`; the 2.3 probe rescore is CPU-only from the model-keyed cache
  (`results/beams_claude-sonnet_v3.jsonl`) and may run in the same job.
- **`kaya/ad_probe_v3.py` generalisation (G3).** Its `--ad_backend api` swap point
  exists; extend so the **SchemaLinker leg** also resolves from the registry when the
  chosen model is `kind: api` (today it builds the HF adapter SL unconditionally).
  Reuse `80_ad_probe_v3.slurm` with a no-GPU submission variant or flag.
- **`kaya/86_run_evaluation_api_v3.slurm` (G4).** = `81_run_evaluation_v3.slurm`'s v3
  Neo4j block + `67`'s no-GPU/`work`-partition + API-key guard. Runs
  `python -m experiments.run_evaluation config/pipeline.yaml` with
  `active_model: claude-sonnet`.

## Acceptance criteria

1. **Offline tests with a fake Anthropic client** (monkeypatched `messages.create`):
   greedy config (`do_sample=False`) sends `temperature=0.0`; sampling config sends
   the configured temperature; **no request ever contains a `top_p` key**; `n>1`
   issues N calls; client constructed with `max_retries=5`.
2. `candidate_decodings` for an anthropic entry contains no `top_p`; for openai it
   does; the merged `decoding[claude-sonnet]` block written by the sweep carries none.
3. `run_evaluation` resolves `prompt_style="instruct"` for `kind: api` and
   `"completion"` for local (unit-tested beside the existing `_resolve_*` tests);
   full offline suite green; local mistral path byte-identical.
4. Runner scripts exist and pass shellcheck-level sanity (correct partition, no
   `--gres`, v3 data dir, key guard); live execution is 8.3's job.

## Handoff

8.3 runs the gates in order with these runners. `config/pipeline.yaml` flips
`active_model: claude-sonnet` at 8.3 time (config-only); `ANTHROPIC_API_KEY` is
exported in the submitting shell.
