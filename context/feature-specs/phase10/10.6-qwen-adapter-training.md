# 10.6 — Qwen2.5-32B Adapter Training (two-stage: generic Ozsoy → POLE continue-SFT)

**Modules:** a 4k-Ozsoy sample step (`data/ozsoy_{sl,qg}_train_4k.jsonl`), six train YAMLs —
generic: `config/schema_linker_train_qwen_generic.yaml`,
`config/query_generator_train_qwen_generic.yaml`; continue:
`config/{schema_linker,query_generator}_train_qwen_v3.yaml`,
`config/{schema_linker,query_generator}_train_qwen_pole_external.yaml` — Kaya runners
`kaya/98_train_qwen_{sl,qg}.slurm` (generic + its two continues, dependency-gated).
`pipeline/sft.py` gains a `gradient_checkpointing` flag (below); otherwise
`train_schema_linker.py`/`train_query_generator.py` + `run_sft` are reused **verbatim** with
`--model_key qwen2.5-32b` (the `init_adapter_path` continue mechanism from 7.4 is reused as-is).
**Depends on:** 10.5 (locked 4-bit + registry entry), 10.2 (external `pole_ext_*` data), 7.4
(v3 `pole_*` + `ozsoy_*` data already exist). **GPU** (v100-32gb, workflow §7).
**Consumed by:** 10.7 (e2e measures the `_v3`/`_pole_external` adapters; the generic adapter
feeds 10.7's optional adapter-attribution ablation).

---

## Objective

Fine-tune Qwen2.5-32B the **same two-stage way Mistral was trained**, so the model × dataset
matrix compares like with like: a generic Cypher-SFT adapter, then in-domain continue-SFT per
schema. Produces the **Mistral-identical checkpoint layout**
`checkpoints/qwen2.5-32b/{sl,qg}_adapter` (generic) + `{sl,qg}_adapter_v3` +
`{sl,qg}_adapter_pole_external` — the exact `_v3`/`_pole_external` paths `_resolve_model_specs`
builds for `active_model: qwen2.5-32b` at each `dataset_version`, plus the generic adapter that
enables the three-way attribution (no adapter / +generic / +generic+POLE).

**Recipe decision (user, 2026-08-22):** this supersedes the earlier single-stage-from-mixed
plan. Two-stage is chosen because it (a) mirrors Mistral's structure for a clean comparison,
(b) enables the generic-vs-in-domain ablation (Mistral's 2026-07-16 finding, jobs
1061277/1061290), and (c) is **cheaper** — Ozsoy is trained once (2 generic adapters) instead
of replicated inside four mixed adapters (~162h vs the single-stage ~293h), and no single job
exceeds the 72h cap.

## Stage 1 — generic Ozsoy adapters (trained ONCE, shared by both substrates)

A **4,000-row seed=13 sample** of the existing full Ozsoy training files (`data/ozsoy_sl_train_4k.jsonl`
from `ozsoy_schema_linker_train.jsonl` 15,262 rows; `data/ozsoy_qg_train_4k.jsonl` from
`ozsoy_qg_train.jsonl` 32,339 rows). Produce the sample deterministically (a small prep step
or `shuf --random-source` with a fixed seed; record how). Then **from-scratch LoRA** (2.1/2.4
pattern):

- `config/{schema_linker,query_generator}_train_qwen_generic.yaml`: **no**
  `init_adapter_path_name` (fresh `LoraConfig`; `target_modules` from the `qwen2.5-32b`
  registry entry), `num_train_epochs: 3`, `learning_rate: 2.0e-4`, `output_name: {sl,qg}_adapter`,
  data = the 4k sample, eval = `data/ozsoy_{sl,qg}_eval.jsonl`.
- ≈4000 × 3 ÷ batch 1 = 12,000 micro-steps × 14.9s ≈ **49.7h each** (< 72h cap → single job).

## Stage 2 — POLE continue-SFT (four adapters, from the generic)

**Continue-SFT via 7.4's `init_adapter_path` mechanism** (the identical path Mistral's 10.3
uses — no from-scratch special-casing):

- `config/{schema_linker,query_generator}_train_qwen_v3.yaml`:
  `init_adapter_path_name: "{sl,qg}_adapter"` (the Stage-1 generic), `output_name:
  "{sl,qg}_adapter_v3"`, `num_train_epochs: 2`, `learning_rate: 1.0e-4`, data =
  **`data/pole_{sl,qg}_train.jsonl` (POLE-only, 1800 rows — NOT the `_mixed` file)**, eval
  `data/pole_{sl,qg}_eval.jsonl`. ≈1800 × 2 = 3,600 steps ≈ **14.9h each**.
- `config/{schema_linker,query_generator}_train_qwen_pole_external.yaml`: same, with
  `init_adapter_path_name: "{sl,qg}_adapter"`, `output_name: "{sl,qg}_adapter_pole_external"`,
  data = `data/pole_ext_{sl,qg}_train.jsonl` (10.2, ~2000 rows), eval
  `data/pole_ext_{sl,qg}_eval.jsonl`. ≈2000 × 2 ≈ **16.5h each**.

**POLE-only continue (no Ozsoy replay)** is deliberate: it isolates the in-domain contribution
for the attribution story and keeps the total at ~6k rows. Forgetting risk is low (continuing
an already-general adapter, 2 epochs). If 10.7's G1/G3 shows regression on general Cypher, add
a light replay slice and note it — do not pre-emptively mix.

## Required `run_sft` change — gradient checkpointing (10.5 hard finding, applies to ALL Qwen runs)

The 10.5 fit-test proved `run_sft` **OOMs even at batch 1** without gradient checkpointing (it
sets none today), and batch 2 OOMs outright (Qwen's 152k-vocab fp32 logit upcast ≈4 GiB at seq
3584). So every Qwen YAML (generic + continue) uses **`per_device_train_batch_size: 1`** +
**`gradient_accumulation_steps: 32`** + **gradient checkpointing on**, and:

- Thread a `training.gradient_checkpointing` flag (default **False**) from the train config
  into `run_sft`'s `TrainingArguments`; when true also pass
  `gradient_checkpointing_kwargs={"use_reentrant": False}` (required with PEFT/4-bit). Set it
  **true** in all six Qwen YAMLs; leave it **absent/false** in every Mistral YAML so the
  v2/v3/`_pole_external` Mistral runs stay **byte-identical** (regression guard).
- This is a real `pipeline/sft.py` contract touch → record in `decisions-log.md` (workflow §4)
  + the tracker row.

## Compute + scheduling

~162h total GPU wall-clock; **no chaining needed** (every job < 72h). The DAG per role:
generic (≈50h) → its two continues (≈15h each), so `kaya/98_train_qwen_sl.slurm` submits the
SL generic and its v3/external continues with `--dependency=afterok:<generic>`; `99` does the
same for QG. All jobs `--gres=gpu:v100-32gb:2` (train peaks 25.3 GiB single-GPU / 43.5 GiB
total; `device_map="auto"` shards). SL and QG DAGs are independent → run in parallel; with the
four v100-32gb nodes, calendar time ≈ generic 50h + continue 16h ≈ **~66h** best case. The
~162h and the **reduced-scale generic** (4k sample vs Mistral's full 15.3k-SL/32.3k-QG) are the
two acknowledged differences from Mistral — note both in the writeup.

## Acceptance criteria

1. The `run_sft` gradient-checkpointing flag is added and **guarded**: a test (or `git stash`
   A/B) confirms the Mistral SL/QG `TrainingArguments` are byte-identical when the flag is
   absent/false; full offline suite green under `t2c`.
2. Stage 1: both generic runs complete from-scratch at batch 1 + GC, no OOM; `eval_loss`
   decreases on the Ozsoy eval split; `checkpoints/qwen2.5-32b/{sl,qg}_adapter` saved.
3. Stage 2: all four continue-SFT runs complete via `init_adapter_path` from the generic;
   `eval_loss` decreases on each POLE eval split;
   `checkpoints/qwen2.5-32b/{sl,qg}_adapter_{v3,pole_external}` saved; mistral checkpoints
   untouched. Job IDs + losses for all six runs in the tracker row.
4. Quick intrinsic Cov@5 (~25 items) per substrate with the new `_v3`/`_pole_external` SL
   adapter, recorded in the tracker row (fast read before 10.7's full G1).

## Handoff

10.7 runs the gated e2e for Qwen on v3 + external POLE (config only, using the
`_v3`/`_pole_external` adapters) and can additionally measure C2/C3 (or intrinsic Cov@5) with
the generic `{sl,qg}_adapter` for the three-way no-adapter / +generic / +generic+POLE
attribution.
