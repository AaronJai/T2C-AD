# 1.1 — Schema Pattern Extraction

**Module:** `pipeline/schema_linker/pattern_extraction.py`
**Depends on:** 0.1 (imports nothing strictly required, but lives in the package)
**Consumed by:** 1.2 (SL training targets), 1.3 (QG `committed_pattern`).

---

## Objective

Given a gold Cypher query, produce the **schema pattern** string: the structural subset of
the `MATCH` clause that says *which schema elements are used*, with entity-specific values
stripped. This single function is the supervised target for Schema Linker training (1.2) and
the `committed_pattern` for Query Generator training (1.3).

> **Canonical-format contract (important).** The string this function returns *defines* the
> committed-pattern format used everywhere downstream. The QG (3.6) is trained on these
> strings, so any component that produces `SchemaMapping.cypher_syntax` at inference —
> `_build_cypher_pattern` (0.1) and the Disambiguator (3.5) — must emit the *same syntactic
> style* (variable:Label nodes, `-[:TYPE]->` directed relationships, property-name-only
> filters, boolean values retained). If those drift from this function's output, the QG sees
> an unfamiliar pattern format and quality drops. Keep them aligned and test it (see 1.3).

Create empty `pipeline/schema_linker/__init__.py`.

---

## Extraction rules (applied to the `MATCH` clause)

| Gold Cypher element | Kept? | Treatment |
|---------------------|-------|-----------|
| Node labels | ✓ | as-is |
| Relationship types | ✓ | as-is |
| Relationship direction | ✓ | as-is (`-[:T]->` / `<-[:T]-`) |
| Property *names* on relationships | ✓ | kept; non-boolean values stripped to name only |
| Boolean property values (`active:true`) | ✓ | retained — a temporal/state filter is a schema-level decision |
| Property maps on nodes | ✓ if it leaves a boolean; else dropped | keep boolean entries; drop string/int-valued entries; if nothing left, drop the whole map and keep just the label |
| String/integer property *values* | ✗ | stripped |
| Variable names (`p`, `i`) | ✓ | retained for readability |
| `WHERE`, `RETURN`, `WITH`, `ORDER BY`, `LIMIT`, `SKIP` | ✗ | dropped entirely |

**Worked examples (use as acceptance tests):**

```
IN:  MATCH (p:Person {name:'James Whitfield'})-[:LIVES_AT {active:true}]->(l:Location)
     RETURN l.address, l.suburb
OUT: (p:Person)-[:LIVES_AT {active:true}]->(l:Location)

IN:  MATCH (c:Case {case_id:'CASE-001'})-[:CONTAINS]->(i:Incident)<-[:SUSPECTED_OF]-(p:Person)
     RETURN p.name, i.crime_type
OUT: (c:Case)-[:CONTAINS]->(i:Incident)<-[:SUSPECTED_OF]-(p:Person)
```

## Filtering (the caller in 1.2 / 1.3 applies this; extraction just returns None on failure)

A row is excluded from training when any of:
- `extract_schema_pattern` returns `None` (parse failure);
- the extracted pattern contains **no relationship type** (node-only queries don't exercise
  relationship schema linking);
- the extracted pattern fails a final `SyntaxValidator` pass (CyVer).

Expected yield: ~85–90% of the Ozsoy training split.

---

## Edge cases

- **Multiple `MATCH` clauses:** concatenate their patterns (comma- or newline-joined),
  preserving each. Don't merge variables across clauses.
- **Boolean values are kept, all other values stripped** — `{active:true}` stays;
  `{from_date:'2020-01-01'}` becomes `{from_date}` (name only); `{name:'X'}` is dropped.
- **Undirected edges** (`-[:KNOWS]-`) keep their undirected form — do not invent a direction.
- Parse failure must return `None`, never raise — the caller counts exclusions.

---

## Acceptance criteria (all runnable now, no GPU/DB)

1. The two worked examples produce exactly the `OUT` strings shown.
2. A node-only query (e.g. `MATCH (p:Person {name:'X'}) RETURN p`) extracts to `(p:Person)`
   with no relationship — and is therefore *flagged for exclusion* by the relationship-type
   filter (test the filter predicate, not just extraction).
3. A malformed input (unbalanced brackets, empty string) returns `None`.
4. `{active:true}` is retained; `{from_date:'2020-01-01'}` is reduced to `{from_date}`;
   `{incident_id:'INC-001'}` is dropped leaving just the label.

0.1's `_build_cypher_pattern` and 3.5's Disambiguator serialisation must match.
