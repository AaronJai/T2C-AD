# 3.3 — Bayesian Entropy Sub-scorer

**Module:** `pipeline/ambiguity/bayesian_scorer.py` (+ `pipeline/ambiguity/__init__.py`)
**Depends on:** 0.1 (`CandidateMapping`, `EntityLookupResult`), 3.1 (produces the
`CandidateMapping`), 3.2 (produces the `EntityLookupResult`)
**Consumed by:** 3.4 (Ambiguity Detector injects these scores into its prompt).

---

## Objective

Compute `(schema_entropy, entity_entropy)`, both ∈ [0,1], from the Schema Linker's candidate
distribution and the Entity Lookup's posterior distribution. Pure arithmetic — no model. This
is the **secondary** ambiguity signal (the LLM self-assessment in 3.4 is primary, per the
entropy probe finding); it is injected into the AD prompt as evidence, never used as a hard gate.

`(candidate_mapping, entity_lookup) → (schema_entropy: float, entity_entropy: float)`

---

## Definition

```
H(P)   = −∑ pᵢ · log₂(pᵢ)      (0·log₂0 = 0 by convention)
H_norm = H(P) / log₂(k)         k = number of candidates;  H_norm ∈ [0,1]
```

- All mass on one candidate → `H_norm = 0` (no ambiguity at that position).
- Uniform over k → `H_norm = 1` (maximum ambiguity).
- `k ≤ 1` → return `0.0` directly (avoids `log₂(1)=0` division). The log base cancels under
  normalisation, so this matches the natural-log version used in the probe (2.2).

`schema_entropy` = **max** `H_norm` across relationship-type slots (the most ambiguous schema
position drives classification). `entity_entropy` = **max** `H_norm` across entity mentions with
≥2 candidates. Either is `0.0` if no qualifying slot exists.

---

## Implementation

```python
# pipeline/ambiguity/bayesian_scorer.py
"""Secondary ambiguity signal: normalised Shannon entropy over SL and entity distributions."""
from __future__ import annotations

import math

from pipeline.types import CandidateMapping, EntityLookupResult


def _shannon_entropy_normalised(scores: list[float]) -> float:
    """H_norm ∈ [0,1] over a (possibly un-normalised) score list. k≤1 → 0.0; total≤0 → 0.0."""
    k = len(scores)
    if k <= 1:
        return 0.0
    total = sum(scores)
    if total <= 0.0:
        return 0.0
    probs = [s / total for s in scores]
    h = 0.0
    for p in probs:
        if p > 0.0:
            h -= p * math.log2(p)
    return h / math.log2(k)


def compute_ambiguity_scores(
    candidate_mapping: CandidateMapping,
    entity_lookup: EntityLookupResult,
) -> tuple[float, float]:
    """Return (schema_entropy, entity_entropy), both ∈ [0,1].

    schema_entropy: for each mention slot whose candidates are relationship_type (this
      INCLUDES temporal variants — same rel type, with/without {active:true}), compute H_norm
      over the candidate scores; take the max across slots (0.0 if none).
    entity_entropy: for each entity mention with ≥2 candidates, compute H_norm over the
      posterior_scores; take the max across mentions (0.0 if none).
    """
    schema_hs: list[float] = []
    for candidates in candidate_mapping.mentions.values():
        rel = [c for c in candidates if c.element.element_type == "relationship_type"]
        if not rel:
            continue
        schema_hs.append(_shannon_entropy_normalised([c.score for c in rel]))
    schema_entropy = max(schema_hs) if schema_hs else 0.0

    entity_hs: list[float] = []
    for candidates in entity_lookup.entity_mentions.values():
        if len(candidates) < 2:
            continue
        entity_hs.append(_shannon_entropy_normalised([c.posterior_score for c in candidates]))
    entity_entropy = max(entity_hs) if entity_hs else 0.0

    return schema_entropy, entity_entropy
```

## Worked examples (use as tests)

- **High schema entropy:** one slot, four relationship-type candidates at ≈0.25 each →
  `H_norm ≈ 1.0`.
- **Low schema entropy:** one slot, scores `[0.97, 0.02, 0.01]` → `H_norm ≈ 0.1`.
- **Single candidate:** one slot, one candidate (score 1.0) → `0.0`.
- **Temporal:** `rel_1_temporal` slot with `[LIVES_AT{active:true}:0.5, LIVES_AT{}:0.5]` →
  counted in `schema_entropy` (≈1.0 for that 2-way slot); 3.4 labels it temporal from context.
- **Entity:** `"James" → [0.5, 0.5]` → `entity_entropy ≈ 1.0`; `"Danny Kovac" → [1.0]` → 0.0.
- **Empty mappings:** `(0.0, 0.0)`.

---

## Edge cases

| Situation | Behaviour |
|---|---|
| k = 1 (single candidate) | `0.0` (no division by `log₂1`) |
| Scores don't sum to 1 (float drift) | renormalised internally before entropy |
| Empty mention dict / no rel-type slots | `schema_entropy = 0.0` |
| No entity mention with ≥2 candidates | `entity_entropy = 0.0` |
| All scores 0 / total ≤ 0 | `0.0` |

---

## Acceptance criteria (all runnable now — pure arithmetic, no GPU/DB)

1. `_shannon_entropy_normalised([0.25,0.25,0.25,0.25]) ≈ 1.0`; `([1.0]) == 0.0`;
   `([0.97,0.02,0.01])` is small (<0.2); `([0.5,0.5]) ≈ 1.0`.
2. `compute_ambiguity_scores` on a hand-built `CandidateMapping` with a 4-way relationship slot
   and an `EntityLookupResult` with a 2-way "James" mention returns `schema_entropy ≈ 1.0` and
   `entity_entropy ≈ 1.0`.
3. Empty `CandidateMapping.mentions` + empty `entity_mentions` → `(0.0, 0.0)`.
4. A node-label-only slot (no relationship_type candidates) contributes 0 to `schema_entropy`.

## Handoff

`compute_ambiguity_scores(candidate_mapping, entity_lookup) → (schema_entropy, entity_entropy)`.
3.4 calls this, injects both values (plus the candidate/entity context) into the Ambiguity
Detector prompt, and lets the LLM make the final call — entropy informs, the LLM decides.
