# 8.1 — SL API Output Contract (instruct prompt variant + format-tolerant parsing)

**Modules:** `pipeline/schema_linker/prompts.py`, `pipeline/schema_linker/inference.py`,
`pipeline/schema_linker/postprocessing.py`, `pipeline/schema_linker/linker.py`,
`experiments/probe_utils.py` (+ their tests).
**Depends on:** 3.1 (SL), 5.5 (API decoding), 7.3 (v3 integration), 7.5 (frozen
`results/beams_mistral7b_v3.jsonl` cached-beam evidence — used as the no-regression guard).
**Consumed by:** 8.3 (the Claude Sonnet 4.6 gated end-to-end run).

---

## Why this exists

The reverted Claude attempts established empirically that a capable instruct model
answers the SL task **correctly but in its own format**: `(Person)` without the label
colon (parsed as a variable name → label lost), extra property detail
(`{crime_type: 'homicide'}`), and prose/markdown-fenced wrapping. The scoring/parsing
stack — tuned on the fine-tuned Mistral's tidy one-line output — counted nearly all of
it wrong (Cov@5 0.067; a parser-tolerance fix alone lifted it to 0.583). 5.5's flagged
risk ("try the shared prompt first; may need a few-shot variant") has therefore already
been tested: the answer is **both** sides — tell the model the contract (prompt) AND
tolerate drift anyway (parser).

**Locked decisions (user-confirmed 2026-07-13):**
1. Parser tolerance applies **unconditionally** (all backends), not as an API-only
   fork — Cov@5 must stay comparable across backends. The guard is an offline rescore
   of the frozen mistral v3 cached beams proving the local numbers are unchanged.
2. Entropy is computed over **canonical structural signatures**, not raw strings,
   everywhere `probe_utils.normalised_entropy` is used — same rescore guard.
3. The shared train/inference completion prompt (`build_sl_prompt`, 1.2) is **not
   forked**; the API variant is a separate, additive function. This is a deliberate,
   documented exception to 1.2's "do not fork it" rule (record in decisions-log).

---

## Contracts

### 1. API instruct prompt variant (`pipeline/schema_linker/prompts.py`)

- `SL_SYSTEM_API: str` — the instruct-model system text. Must state the output contract
  explicitly: output **exactly one line**, a bare Cypher graph pattern; labels carry a
  leading colon (`(:Person)`, never `(Person)`); relationship types in brackets
  (`-[:SUSPECTED_OF]->`); the ONLY permitted property filter is `{active: true}` on
  temporal relationships; no entity-specific values, no WHERE/RETURN, no prose, no
  markdown fences.
- `build_sl_prompt_api(question, schema_block) -> str` — same schema block + question
  layout as `build_sl_prompt`, plus **2–3 authored few-shot examples** (grounded in the
  v3 schema, mirroring the 3.4/3.5 few-shot style) demonstrating: a single-hop role
  edge, a temporal `{active: true}` variant, and a 2-hop chain. Few-shots target the
  reverted-attempt residuals (dropped active filter; over-chaining an extra hop).
- `build_sl_prompt` and `SL_SYSTEM` remain **byte-identical** (training-data contract).

### 2. Prompt selection (`linker.py`, `probe_utils.py`)

- `SchemaLinker(llm, beam_k=5, ..., *, decoding=None, prompt_style="completion")` —
  keyword-only, default preserves current behaviour. `"instruct"` → `build_sl_prompt_api`.
  `link()`'s 3.1 signature unchanged.
- `probe_utils.generate_beams(llm, question, schema_block, decoding, *,
  prompt_style="completion")` — same selection, so the sweep/probe/G1 decode exactly as
  the live SL.
- Callers (5.4 `run_evaluation`, 2.2 sweep, 2.3 probe, the 8.2 G1 runner) pass
  `prompt_style="instruct"` when the registry entry is `kind: api` — the wiring itself
  lands with those callers in 8.2; this step only exposes the parameter.

### 3. Tolerant extraction (`inference.py::extract_pattern_from_completion`)

Replace "first non-empty line" with:
1. Strip markdown code fences (reuse/mirror the QG `_FENCE_RE` approach — take fenced
   content when present).
2. Return the first line that **structurally looks like a pattern** — contains a
   parenthesised node group `(` … `)` — skipping prose lines.
3. Fallback: current behaviour (first non-empty line / stripped text), so bare-pattern
   input is byte-identical to today.

### 4. Colon-less label repair (`postprocessing.py::parse_schema_pattern`)

When `_parse_node` yields an alias with **no label** and the alias is an **exact,
case-sensitive match** for a label in `schema.node_labels`, treat it as the label
(alias becomes anonymous). Real aliases (`(p)`, `(x)`) are untouched. Extra node/rel
property filters (e.g. `{crime_type: 'homicide'}`) are already captured in `props` and
must remain non-invalidating — assert this in a test; only `active` stays semantically
load-bearing (`_has_active`).

### 5. Canonical-pattern entropy (`probe_utils.py::normalised_entropy`)

Count distinct **`_canonical_pattern` signatures** instead of distinct raw strings —
the same direction-/dangling-connector-invariant comparison `covered()` already uses —
so superficial phrasing variation across sampled completions no longer inflates
entropy (which would corrupt the 8.3 temperature sweep and entropy-probe AUC).
**Junk guard:** when a beam's signature is empty (no relationships AND no bare
labels — i.e. unparseable/garbage), fall back to the raw string as its signature, so
distinct garbage completions keep counting as distinct outcomes (matching today's
behaviour for junk).

## Acceptance criteria

1. **Offline unit tests** (no GPU/API): fenced + prose-wrapped completions extract the
   bare pattern; `(Person)-[:SUSPECTED_OF]->(Incident)` parses with both labels
   repaired; `(p:Person)` and `(p)` behave exactly as before; extra property maps do
   not invalidate a beam; `build_sl_prompt` output byte-identical to pre-8.1;
   `build_sl_prompt_api` contains the format contract + few-shots;
   `normalised_entropy` collapses format-variant duplicates and keeps junk distinct.
2. **No-regression rescore guard (GPU-free, from the frozen cache):** recompute the
   7.5 G1/G2 evidence from `results/beams_mistral7b_v3.jsonl` under the new parsing +
   entropy code — full-120 Cov@5/EM@1 and the locked-dp entropy AUC must be unchanged
   (G1 0.683/0.667 at dp=0.2; dp=1.0 Cov@5 0.725; probe AUC 0.689). Any delta stops
   the step and goes to decisions-log before proceeding.
3. Full offline suite green under the `t2c` env; the local (beam, completion-prompt)
   path is byte-identical end-to-end.

## Handoff

8.2 wires `prompt_style` from the registry `kind` into the run harness, sweep, probe,
and gate runners; 8.3's G0.5 smoke eyeballs raw Claude completions against this
parser. The prompt-variant exception to 1.2 and the entropy-basis change are recorded
in decisions-log with the rescore evidence.
