# 3.8 — DB Executor

**Module:** `pipeline/execution/db_executor.py` (+ `pipeline/execution/__init__.py`)
**Depends on:** 0.1 (`ExecutionResult`). **Requires a live Neo4j.**
**Consumed by:** 4.1 (Semantic Evaluator compares this result set to ground truth); orchestrator.

---

## Objective

Execute a validated Cypher query against Neo4j and return its result set as a list of record
dicts, with timing and robust error capture. A timeout guards against pathological traversals
(variable-length / shortest-path queries that the benchmark contains).

`(cypher, driver, database, timeout_s) → ExecutionResult`

Only queries CyVer routed to `accept` (3.7) reach here.

---

## Implementation

```python
# pipeline/execution/db_executor.py
"""Execute validated Cypher against Neo4j; capture results, timing, and errors."""
from __future__ import annotations

import time

import neo4j
from neo4j.exceptions import Neo4jError

from pipeline.types import ExecutionResult


def db_executor(
    cypher: str,
    driver: neo4j.Driver,
    database: str = "neo4j",
    timeout_s: float = 10.0,
) -> ExecutionResult:
    """Run cypher in a read session; collect records as list[dict]; time it; map errors.

    - Use a transaction with a server-side timeout (version-appropriate mechanism, e.g.
      session.execute_read with a tx that sets timeout, or a managed transaction with
      tx_timeout) so pathological queries can't hang the run.
    - records: [record.data() for record in result] — each a plain dict.
    - On neo4j.exceptions.* (syntax, constraint, timeout, transient): return
      ExecutionResult(success=False, result_set=[], error=str(e), execution_time_ms=elapsed).
    - On success: ExecutionResult(success=True, result_set=records, error=None,
      execution_time_ms=elapsed).
    """
    start = time.perf_counter()
    try:
        with driver.session(database=database) as session:
            def _run(tx):
                result = tx.run(cypher)
                return [record.data() for record in result]
            records = session.execute_read(_run)   # set a tx timeout per driver version
        elapsed = (time.perf_counter() - start) * 1000.0
        return ExecutionResult(success=True, result_set=records, error=None,
                               execution_time_ms=elapsed)
    except Neo4jError as e:
        elapsed = (time.perf_counter() - start) * 1000.0
        return ExecutionResult(success=False, result_set=[], error=str(e),
                               execution_time_ms=elapsed)
```

> The exact timeout mechanism varies by `neo4j` driver version (transaction `timeout` config vs
> `execute_read` metadata). Set a server-side transaction timeout of `timeout_s`; if the installed
> driver exposes it differently, adapt and note it in `decisions-log.md`. Catch the broadest
> relevant neo4j exception base so timeouts and transient errors are captured as
> `success=False`, not raised.

## Edge cases

| Situation | Behaviour |
|---|---|
| Query returns rows | `success=True`, `result_set` = list of `record.data()` dicts |
| Query returns no rows | `success=True`, `result_set=[]` (empty ≠ failure) |
| Syntax/runtime error (shouldn't happen post-CyVer, but possible) | `success=False`, `error=str(e)` |
| Timeout (pathological traversal) | `success=False`, `error` notes timeout |
| Records contain nodes/relationships | `record.data()` returns their property dicts; nested structures preserved as plain types |

Note: a `success=True, result_set=[]` is a legitimate outcome that 4.1 evaluates against the
ground-truth result set (which may also be empty for some questions).

## Acceptance criteria

Now (no DB):
1. The module imports; `db_executor`'s contract (signature, `ExecutionResult` fields) matches 0.1.
2. With a fake driver/session whose `execute_read` returns `[{"name": "X"}]`, `db_executor` returns
   `success=True, result_set=[{"name":"X"}]`, `execution_time_ms` a positive float.
3. With a fake session that raises a `Neo4jError`, returns `success=False, result_set=[],
   error=<message>`, and still sets `execution_time_ms`.

Run for real on Kaya (a live Neo4j loaded with SyntheticPoliceKG is available — see
`ai-workflow-rules.md` §7; `sbatch kaya/55_neo4j.slurm`, reach `bolt://localhost:7687` via
`srun --jobid=<id> --overlap`):
4. Real queries against the loaded POLE graph return expected rows; a deliberately heavy
   variable-length query hits the timeout and returns `success=False` with `execution_time_ms` set.
