# 0.3 — POLE Schema Builder

**Module:** `pipeline/schema.py`
**Depends on:** 0.1 (imports `SchemaRepr`)
**Consumed by:** 3.1, 3.4, 3.6, 5.1, 6.1 (every stage that injects schema into a prompt).

---

## Objective

Construct the one canonical `SchemaRepr` for the SyntheticPoliceKG (POLE) graph. The
`SchemaRepr` dataclass and its serialisers live in `0.1`; this step only provides the
POLE-specific *contents* — the 9 node labels, 28 relationship paths, and per-label /
per-edge property lists. Built once from fixed definitions; not read from Neo4j at runtime.

> The properties dict carries both **node** property lists and the **temporal edge**
> property lists (`from_date`/`to_date`/`active`/…) — the edge entries are what let the
> Query Generator and pattern extractor reason about temporal filters.

## Edge cases

- The four `Person→Incident` edges (`SUSPECTED_OF`, `WITNESSED`, `VICTIM_OF`,
  `INVESTIGATES`) are intentionally all present — they are the primary source of *schema*
  ambiguity and must all appear so the Schema Linker can produce a spread over them.
- `properties` mixes node labels and edge types as keys. Consumers that iterate node
  properties (e.g. `to_prompt_string`) render all keys uniformly; that's fine — the edge
  entries simply appear as additional "Properties" lines.
- This builder must stay in sync with `SyntheticPoliceKG.cypher`. It is the prompt-facing
  schema; if it lists an edge the DB lacks (or omits one), prompts mislead the model even
  though CyVer (which checks the live DB) would still catch generated errors.

## Acceptance criteria

Now (no DB; needs the repo's `SyntheticPoliceKG.cypher`):
1. `build_pole_schema_repr()` returns a `SchemaRepr` with exactly 9 `node_labels` and 28
   `relationship_paths`.
2. **Schema-consistency test:** the set of `relationship_paths[*]["type"]` equals the set
   of relationship types defined in `SyntheticPoliceKG.cypher`, and the set of
   `node_labels` equals the set of node labels defined there. (Parse the `.cypher` file in
   the test.)
3. `to_prompt_string(include_properties=True)` contains the substrings `Nodes:`, `Paths:`,
   and `Properties:`; `to_cypher_syntax()` emits one `(...)-[:TYPE]->(...)` line per path.

Deferred (integration, `@pytest.mark.integration`):
4. Against a live Neo4j with the KG loaded, every label and relationship type returned by
   `db.schema.visualization()` (or `CALL db.relationshipTypes()` / `db.labels()`) is
   present in the builder, and vice versa.

## Handoff

`build_pole_schema_repr()` is importable from `pipeline.schema`. Stages that build prompts
call it (often once, cached in `PipelineComponents` at 5.1) and serialise via the
`SchemaRepr` methods from 0.1. No consumer constructs a `SchemaRepr` by hand.
