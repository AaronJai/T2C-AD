**Modules:** `pipeline/llm/anthropic.py`, `pipeline/schema_linker/inference.py`,
`pipeline/schema_linker/linker.py`, `experiments/build_condition{1,2,3}.py`,

**Consumed by:** the researcher running the benchmark on an API model (Anthropic/OpenAI).

---

## Why this exists

The original specs (5.3/5.4, 2.2/2.3) assumed an API model would only swap in for the
**Ambiguity Detector / Disambiguator** (the `ad`/`dis` config points), leaving the Schema
Linker and Query Generator pinned to a local fine-tuned base + LoRA adapters. In real use **one
model runs the whole pipeline**. This step removes the local-only assumptions so setting
`active_model` to an API entry (plus an API key) runs **C1/C2/C3 and the sweep/probe**
end-to-end with that single model — no code edits. The local fine-tuned path is unchanged.

---

## Locked design decisions (user-confirmed 2026-06-30)

1. **SL candidate distribution for an API model = temperature sampling.** Diverse beam search
   (beam groups + per-beam logprobs) is HuggingFace-only. The contribution is "distribution, not
   argmax" — not "beam search specifically" — so an API backend samples `k` completions at a
   locked temperature and aggregates them with the *same* `build_candidate_mapping`. OpenAI feeds
   real summed-logprob scores; Anthropic feeds uniform `-1.0` scores → **frequency weighting**
   (a pattern sampled `m` times scores `logsumexp(m × −1.0) = −1.0 + log m`).
2. **C2/C3 are stage-presence, not SFT, for an API model.** An API model isn't fine-tuned and
   has no adapters. C1 = zero-shot QG; C2 = + schema-linking candidate distribution + committed
   pattern in the QG prompt; C3 = + disambiguation. C2 isolates the schema-grounding **stage**,
   not fine-tuning. The monotonic-ordering claim (C3 ≥ C2 ≥ C1) is retained under this framing.
3. **Sweep/probe generalize to a temperature sweep.** The full methodology (incl. the entropy
   probe) runs on any backend; the swept knob is `diversity_penalty` (local) or `temperature` (API).

## Contracts

### SL decoding strategy
- `pipeline/schema_linker/inference.py::sl_sampling_config(num_samples, temperature, top_p=1.0)
  -> GenerationConfig` (the API strategy) alongside the unchanged `sl_generation_config` (beam).
- `SchemaLinker(llm, beam_k=5, diversity_penalty=1.0, min_valid_beams=1, *, decoding=None)`.
  `decoding={"strategy":"sample","temperature":...,"top_p":...}` → sampling; `None`/`"beam"` →
  diverse beam search (default, byte-identical to before). `beam_k` is the number of completions
  in both modes and the entropy-normalisation divisor. `link()`'s 3.1 signature is unchanged.

### LLM backend
- `AnthropicLLM.generate_chat` issues `num_return_sequences` independent calls (the Messages API
  has no `n`), returning that many `Completion`s with uniform score `-1.0`. The single-output
  AD/Dis path (n=1) is unchanged. `OpenAILLM` already maps `num_return_sequences → n` + logprobs.

### Decoding config (`config/schema_linker_inference.yaml`)
```yaml
decoding:
  mistral7b:     { strategy: beam,   diversity_penalty: 0.2, k: 5 }
  claude-sonnet: { strategy: sample, temperature: 0.7, top_p: 0.95, k: 5 }
diversity_penalty: 0.2   # legacy flat mirror — back-compat for local readers
```
The 2.2 sweep writes the active model's `decoding[<key>]` block (merging, not clobbering others).

### Registry (`config/models.yaml`) + run harness
- API entries carry `kind: api`, `backend`, `model`; local entries are implicitly `kind: local`.
- `run_evaluation._resolve_model_specs(entry, key)` → `(base_spec, sl_spec, qg_spec, kind)`:
  local = HF base + namespaced SL/QG adapters (+ registry 4-bit/dtype); api = the same API spec
  three times (no adapters). `_resolve_sl_decoding(sli, key, kind)` reads `decoding[key]` (local
  falls back to flat `diversity_penalty`); fails loud otherwise.
- `build_condition2(*, ..., sl_spec, qg_spec, schema)`;
  `build_condition3(*, ..., base_spec, sl_spec, qg_spec, schema, sl_decoding, ad_spec=None,
  dis_spec=None, embedding_model=None)`. HF-only 4-bit/device-pinning is guarded by
  `spec["backend"] == "huggingface"`; API specs pass through untouched.

### Sweep + probe
- `probe_utils.generate_beams(llm: BaseLLM, question, schema_block, decoding: dict)` — beam or
  sample per `decoding`; reuses the SL inference configs so beam-mode output is byte-identical.
- `diversity_penalty_sweep` sweeps `PENALTIES` (local) or `TEMPERATURES` (API); `select_penalty`
  kept (back-compat) over a generalized `_select_row`; `write_inference_config(model_key, decoding,
  path)` merges the per-model block. `entropy_probe.read_sl_decoding` + model-keyed cache paths.

## Acceptance criteria

1. Offline suite green, local path byte-identical (decoding defaults to beam). **(met: 258 passed)**
2. `active_model: mistral7b` resolves beam decoding + adapters as before; an API `active_model`
   resolves the same API spec for every stage, no adapters, sampling decoding. **(met: tests)**
3. `AnthropicLLM` returns N completions for `num_return_sequences=N`; the SL builds a
   `CandidateMapping` under sampling. **(met: tests)**
4. **Deferred (API key + live Neo4j):** a small API smoke run — the sweep writes a sampling
   `decoding` block, and `run_evaluation` over a few questions produces C1/C2/C3
   `EvaluationResult`s with a multi-candidate SL mapping (non-zero schema entropy on an ambiguous
   item). Then the full 125×3 API run → `results/tables_{api_key}.md`.

## Flagged risks (validate during the API smoke run; do not pre-build)
- **SL prompt for a non-fine-tuned model.** `build_sl_prompt` was authored as a *completion*
  prompt for the fine-tuned Mistral; a capable instruct model should follow it, but may need a
  few-shot variant to reliably emit the bare pattern line. Try the shared prompt first.
- **Cost/latency.** Anthropic SL at `k=5` is 5 calls/question/attempt; `k` (`num_samples`) is the
  tuning knob.
- **Run environment.** API runs need **no GPU** but still need **live Neo4j** (Entity Lookup,
  CyVer, executor, evaluator) — see `kaya/67_run_evaluation_api.slurm`.
