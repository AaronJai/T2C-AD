# 3.2 — Entity Lookup

**Modules:** `pipeline/entity_lookup/registry.py`, `cache.py`, `span_extractor.py`,
`matcher.py`, `lookup.py` (+ `__init__.py`)
**Depends on:** 0.1 (`EntityCandidate`, `EntityLookupResult`, `CandidateMapping`), 3.1
(`CandidateMapping` for label scope). **Requires a live Neo4j** (cache load).
**Consumed by:** 3.3 (entity entropy), 3.4/3.5 (entity context), 5.1 (`PipelineComponents`
loads the cache).

---

## Objective

Resolve NL entity mentions ("Danny Kovac", "Northbridge", "Operation Ironside") to **real KG
node instances** by fuzzy-matching question spans against actual node property values queried
from Neo4j. Produce a posterior distribution per mention — one clear match → low entity
entropy; spread across several → high. This is the grounding that makes entity-ambiguity
detection verifiable rather than the LLM guessing from text alone.

`(question, candidate_mapping, cache) → EntityLookupResult`

> **Live DB, not the schema file.** The cache reads real property *values* (names, suburbs,
> case names) from the running database. `SyntheticPoliceKG.cypher` defines only structure.

**Types:** `EntityCandidate` / `EntityLookupResult` come from `pipeline.types` (0.1).
`CachedNode`, `EntityCache`, `ENTITY_REGISTRY` are defined **here** (component-local), and
`PipelineComponents` (5.1) imports `EntityCache`.

## `cache.py` — in-memory entity cache (loaded once)

```python
# pipeline/entity_lookup/cache.py
from __future__ import annotations
from dataclasses import dataclass
from typing import Optional
import neo4j
from pipeline.entity_lookup.registry import ENTITY_REGISTRY


@dataclass
class CachedNode:
    node_id: str
    label: str
    name_values: list[str]      # all non-null name_prop values
    display_name: str           # first non-null name_prop value
    extra: dict[str, str]       # extra_props for disambiguation context


class EntityCache:
    def __init__(self, nodes: list[CachedNode]):
        self.nodes = nodes
        self._by_label: dict[str, list[CachedNode]] = {}
        for n in nodes:
            self._by_label.setdefault(n.label, []).append(n)

    def for_labels(self, labels: list[str]) -> list[CachedNode]:
        out: list[CachedNode] = []
        for label in labels:
            out.extend(self._by_label.get(label, []))
        return out

    @classmethod
    def load(cls, driver: neo4j.Driver, database_name: Optional[str] = None) -> "EntityCache":
        """One Cypher query per registered label; build CachedNodes. Skip nodes with no
        non-null name value. Loaded once per PipelineComponents (5.1), immutable thereafter."""

```

`load` runs `MATCH (n:{label}) RETURN n.{id_prop} AS …, n.{name_prop} AS …, …` per registry
entry and constructs `CachedNode`s. (Reference body in Pass 5 §1.3 — straightforward.)

## `matcher.py` — fuzzy match + Bayesian posterior

```python
# pipeline/entity_lookup/matcher.py
from __future__ import annotations
from rapidfuzz import fuzz
from pipeline.entity_lookup.cache import CachedNode


def fuzzy_match_score(span: str, candidate_name: str) -> float:
    """token_set_ratio / 100 ∈ [0,1] — robust to word order and partial (first-name) matches."""
    return fuzz.token_set_ratio(span.lower(), candidate_name.lower()) / 100.0


def compute_posterior_scores(
    span: str, candidates: list[CachedNode], fuzzy_threshold: float = 0.75,
) -> list[tuple[CachedNode, float, float]]:
    """Per candidate: match_score = max over its name_values. Keep those ≥ threshold.
    Uniform prior 1/n over kept candidates; posterior ∝ prior × match_score, normalised to sum 1.
    Return (node, match_score, posterior) ordered by posterior desc; empty if none clear threshold."""

```

## Edge cases

| Situation | Behaviour |
|---|---|
| Span matches nothing ≥ threshold | omitted from `entity_mentions`; contributes 0 entity entropy |
| Exactly one match | included with `posterior_score=1.0` → entity_entropy 0 (no ambiguity) |
| > `max_candidates_per_mention` | keep top-N by posterior; log a warning (over-generic span) |
| Multiple genuine matches ("James" → 2 people) | full posterior distribution → non-zero entity entropy |
| Label scope empty | always includes Person + Organisation, so never empty |

## Acceptance criteria

Now (no DB; hand-built `CachedNode`s):
1. `extract_entity_spans("Show incidents linked to James Whitfield in Northbridge")` returns
   `["James Whitfield", "Northbridge"]` (longest-first, deduped), not the leading question word.
2. `fuzzy_match_score("James", "James Whitfield")` is high (≥ 0.75); `compute_posterior_scores`
   over two "James" nodes returns two candidates with posteriors summing to ~1.0, ordered desc.
3. `entity_lookup` with a hand-built cache: a span with one match → posterior 1.0; a span with
   two matches → two candidates; a no-match span → absent from `entity_mentions`.
4. `_candidate_labels` always includes Person and Organisation.

Deferred (live Neo4j): `EntityCache.load(driver)` returns the expected counts (≈35 Person,
5 Organisation, 4 Case, 18 Location name-searchable nodes) — verified in 5.1 integration.

## Handoff

`entity_lookup(...) → EntityLookupResult` and `EntityCache` (loaded by 5.1 from the live driver).
3.3 reads `entity_mentions` posteriors for entity entropy; 3.4/3.5 inject the matched candidates
as prompt context so the LLM reasons over *real* KG instances, not guesses.
