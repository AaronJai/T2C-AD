# 3.7 — CyVer Validation

**Module:** `pipeline/validation/cyver_validator.py` (+ `pipeline/validation/__init__.py`)
**Depends on:** 0.1 (`ValidationResult`, `RoutingTarget`). **Requires a live Neo4j** (CyVer
validates by querying the running graph). The three validator instances are built in 5.1
(`PipelineComponents`) and passed in.
**Consumed by:** 3.8 (only `route_to="accept"` queries are executed); orchestrator (routes
failures upstream by `route_to`).

---

## Objective

Deterministically validate a generated Cypher query in three stages and **route each failure
type to a different upstream stage**. This typed routing is what turns CyVer from a pass/fail
gate into the pipeline's structural-repair mechanism.

`(cypher, components) → ValidationResult`

Routing (the contract):

| Stage | Failure condition | `error_type` | `route_to` |
|-------|-------------------|--------------|------------|
| Syntax | `validate()` returns `False` | `"syntax"` | `"query_generator"` |
| Schema | `score < 1.0` | `"schema"` | `"schema_linker"` |
| Properties | `score is not None and score < 1.0` | `"properties"` | `"schema_linker"` |
| (all pass) | — | `None` | `"accept"` |

`properties_score is None` (query accesses no properties) is **not** a failure → proceed to accept.

---

## The real CyVer API (Pass 1 correction)

All three validators take a **`neo4j.Driver`** and validate against the live graph
(`SyntaxValidator` uses `EXPLAIN`; `SchemaValidator` uses `EXISTS { MATCH … }`). **`SchemaRepr`
is never passed to CyVer** — there is no `to_cyver_format()`. Validators are constructed once in
5.1 (constructing per-call would re-query schema metadata each time).

```python
from CyVer import SyntaxValidator, SchemaValidator, PropertiesValidator
# built once in PipelineComponents.build():
#   sv  = SyntaxValidator(driver, check_multilabeled_nodes=True)
#   schv = SchemaValidator(driver)
#   pv  = PropertiesValidator(driver)
# validate() return shapes:
#   (is_valid: bool,           metadata: list[dict]) = sv.validate(query, database_name=None)
#   (score: float,             metadata: list[dict]) = schv.validate(query, database_name=None)
#   (score: float | None,      metadata: list[dict]) = pv.validate(query, database_name=None, strict=False)
```

CyVer (Mandilara et al.) is installed per its README and is a project dependency.

## Implementation

```python
# pipeline/validation/cyver_validator.py
from __future__ import annotations

from typing import TYPE_CHECKING

from pipeline.types import ValidationResult

if TYPE_CHECKING:                       # avoid a runtime import cycle with 5.1
    from pipeline.components import PipelineComponents


def cyver_validator(cypher: str, components: "PipelineComponents") -> ValidationResult:
    """Run Syntax → Schema → Properties against the live graph; return on first failure.

    Uses the pre-built validators and database_name held on `components` (duck-typed:
    components.syntax_validator / schema_validator / properties_validator / database_name).
    """
    db = components.database_name

    syntax_valid, syntax_meta = components.syntax_validator.validate(cypher, db)
    if not syntax_valid:
        return ValidationResult(syntax_valid=False, schema_score=0.0, properties_score=None,
                                error_type="syntax", route_to="query_generator", metadata=syntax_meta)

    schema_score, schema_meta = components.schema_validator.validate(cypher, db)
    if schema_score < 1.0:
        return ValidationResult(syntax_valid=True, schema_score=schema_score, properties_score=None,
                                error_type="schema", route_to="schema_linker", metadata=schema_meta)

    props_score, props_meta = components.properties_validator.validate(cypher, db)
    if props_score is not None and props_score < 1.0:
        return ValidationResult(syntax_valid=True, schema_score=schema_score, properties_score=props_score,
                                error_type="properties", route_to="schema_linker", metadata=props_meta)

    return ValidationResult(syntax_valid=True, schema_score=schema_score, properties_score=props_score,
                            error_type=None, route_to="accept", metadata=[])
```

---

## Edge cases

- **`properties_score is None`** (no properties accessed) → accept; do not route to schema linker.
- **Short-circuit:** stages run in order and return on first failure; a syntactically invalid query
  is never schema/property-checked (and never executed).
- **`metadata`** carries CyVer's structured warning/error dicts (e.g. `UnknownLabelWarning`) and is
  retained in `PipelineState` for error analysis and thesis reporting (Table 3 repair metrics, 4.2).
- The schema/properties routes both go to the **Schema Linker**, not the Query Generator — the
  pipeline's deliberate choice (a wrong label/property is a linking error, not a generation typo).
- No `SchemaRepr` is passed; do not reintroduce it.

---

## Acceptance criteria

Now (no DB; fake `components` with stub validators returning canned `(result, metadata)`):
1. Stub syntax `False` → `error_type="syntax"`, `route_to="query_generator"`, `metadata` passed through.
2. Stub syntax `True`, schema `0.5` → `error_type="schema"`, `route_to="schema_linker"`.
3. Stub syntax `True`, schema `1.0`, properties `0.5` → `error_type="properties"`,
   `route_to="schema_linker"`.
4. Stub syntax `True`, schema `1.0`, properties `None` → `error_type=None`, `route_to="accept"`,
   `properties_score=None`.
5. Stub syntax `True`, schema `1.0`, properties `1.0` → `route_to="accept"`.

Deferred (live Neo4j + CyVer): the real validators flag a genuinely invalid query and accept a
valid one — exercised in 5.1/5.4 integration.

---

## Handoff

`cyver_validator(cypher, components) → ValidationResult`. The orchestrator (5.2) reads `route_to`:
`accept` → DB executor (3.8); `query_generator` → regenerate (inner loop, ≤2); `schema_linker` →
re-link (outer loop, ≤3). The validator instances are created in 5.1; this function only consumes
them.
